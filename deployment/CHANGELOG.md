# 功能修改记录

## 2026-11-06：高清可视化与坐标翻转修复

- 将俯视导出升级到可配置的 3600×3000 像素；保留 DPI、覆盖透明度、颜色与轨迹线宽控制。
- 彩色 mesh 底图从随机 50 万散点改为全顶点的米制栅格颜色聚合，默认约 6 cm/像素，并对颜色总和与权重分别平滑，减轻碎点与背景泛白。
- 修复底图行方向与世界 Z 轴不一致的问题。图像第一行对应 Z 最大侧，第一列对应 X 最小侧；加入非对称四角回归用例，并修正边界点遗漏。
- 新增原始底图 PNG、坐标 JSON，以及 YAML 控制的局部高清放大图。
- 新增 `--visualize-only`，复用已有路线与 NavMesh 刷新可视化，不重复生成视频、不重新烘焙。
- 独立刷新入口可生成真实 Habitat-GS 高斯俯视 RGB，并按每个 NavMesh 顶点的高度做同相机透视投影叠加。
- 忽略全密度资产与本地输出目录，禁止提交原始 PLY、视频和大型生成文件。

验证：语法检查、`git diff --check`、四角坐标及俯视透视坐标测试通过；使用全密度场景完成全场及三张局部图生成，核对道路与 NavMesh 对齐。

已知限制：高空高斯俯视拉丝明显，不能用其验证精细障碍；mesh 颜色聚合不是带深度遮挡的正射产品；低柱和树冠是否误判仍需几何核验。本次没有改变碰撞 mesh、正式 NavMesh 或重新生成 50 条视频。

## 2026-11-06：高斯/NavMesh 投影修复

- 自检发现 Gaussian/NavMesh 图将世界 XYZ 数据混入图像像素绘制接口，导致 NavMesh 多边形错位；现改为独立像素 XY 三角面，并按 `+Z` 对应相机图像上方投影。
- 正常单路线 pipeline 现在也按开启的 YAML 开关输出 `gaussian_topdown_raw.png` 与 `gaussian_navmesh_topdown.png`；不再只有 `--visualize-only` 才生成。
- 新增顶点高于相机时显式报错，避免输出无效透视图。

验证：俯视投影左右/上下方向与相机高度检查通过；重新用全密度原始俯视 PNG 生成了对齐版本。高空 Gaussian 本身仍有拉丝，质量限制未解决。

## 2026-11-06：相机轨迹先验、树区诊断和文档整理

- 默认使用 `Wanda Plaza/cameras.json` 的相机中心作为可行区域先验；源 Z-up 坐标转为 Habitat `(x,z,-y)`。路径以 10 m 默认缓冲约束，阈值和开关都在 YAML。
- 起终点默认优先由采集相机 XYZ 位置投影到 NavMesh 后抽取；相机朝向不复用。路径全段采样需处于缓冲区，手工端点同样受约束。
- 解析后的相机轨迹和 KD-tree 在 50 条路线批次中缓存；选定 island 时只使用该岛上的采集端点。
- 除 geodesic 候选路径外，验证还检查实际逐帧导航轨迹都留在轨迹缓冲内，避免简化路径折线漏掉移动点。
- 右上树区候选点初筛显示少数 NavMesh 点靠近高处绿色几何，最近障碍距离低于 0.25 m 代理半径。临时 5 cm/2.5 cm 栅格、5 cm climb 网格虽增加岛数且减少导航面积，候选点旁仍有可行走点；此结果提示需要检查碰撞资产，但不能仅据颜色断言其为树干，正式 NavMesh 未修改。
- 整理 README 并新增图像判读与先验说明页；文档明确高空 Gaussian 拉丝和 mesh 顶视无深度遮挡等限制。
- 初次全密度 smoke test 未留下输出，没有作为验证证据。随后使用 640×540 俯视配置完成全密度单路线 smoke test：400 帧 RGB、93.4 m 路线、全部移动点可行走、采集轨迹缓冲检查通过，并生成 Gaussian 俯视原图/叠加图。`--visualize-only` 刷新模式也通过。
- Gaussian 高空图作为可选输出，默认关闭，避免每条路线增加 3600×3000 额外渲染；`--bake-only` 会跳过 Gaussian RGB 生成。
